# 앱 사이드메뉴 정책

> 초안 — 인용하지 말 것 (팀 확정 후 이 줄을 지운다)

> **한 줄 요약** — 앱 사이드메뉴(설정)와 하위 화면(계정 정보 S-002 · 서비스 이용약관 · 개인정보 처리 방침 · 탈퇴 알림창 S-003)의 화면 구성, 닉네임 수정 유효성 검사, 서비스 탈퇴 동작과 문구를 규정한다.
>
> **강제성** — 필수 사항이다. 구현이 이 문서와 다르면 버그로 처리하고, 동작을 바꾸려면 이 문서를 먼저 개정한다.

## 1. 목적

이 문서는 사이드메뉴 영역의 화면 구성·동작·문구를 한 곳에 규정해, 기획·구현·QA가 같은 기준을 보도록 한다.

## 2. 적용 범위

- **적용 대상**: 사이드메뉴(설정) 화면과 그 하위 화면 — 계정 정보(S-002), 서비스 이용약관, 개인정보 처리 방침, 탈퇴 알림창(S-003)
- **적용 제외**:
  - 닉네임 초기 자동 생성 규칙(계정 생성 시 1회 적용) — 계정 생성 정책에서 다룬다
  - 그룹 내 닉네임 화면 — 단, 닉네임 유효성 규칙(§3.2.1~§3.2.4)은 그룹 내 닉네임에도 공통 적용된다

## 3. 규칙

> 규칙이 8개를 넘어 화면 단위로 §3.1~§3.3 으로 묶는다. 인용은 `SM-001 §3.2.4` 형태로 한다.

### 3.1 설정 화면

- **3.1.1** 설정 화면은 위에서부터 ① 내 프로필 카드 ② 설정 목록(계정 정보 · 서비스 이용약관 · 개인정보 처리 방침 · 버전 정보) ③ 위험 액션(로그아웃 · 서비스 탈퇴하기) 순으로 구성해야 한다.
- **3.1.2** 내 프로필 카드는 앱 닉네임과 로그인 제공자(예: Kakao)를 표시해야 한다.
- **3.1.3** 서비스 이용약관과 개인정보 처리 방침은 인앱 웹뷰로 표시해야 한다.
- **3.1.4** 버전 정보 행은 현재 앱 버전을 표시만 하며, 탭했을 때 어떤 동작도 해서는 안 된다.

### 3.2 계정 정보 — 닉네임 수정 (S-002)

- **3.2.1** 사용자는 닉네임에 한글·영문·숫자·공백만 입력할 수 있으며, 특수문자와 이모지는 입력할 수 없다.
- **3.2.2** 닉네임은 1자 이상 15자 이하여야 하며, 공백도 1글자로 센다.
- **3.2.3** 닉네임의 맨 앞과 맨 뒤에는 공백을 넣어서는 안 된다.
- **3.2.4** 글자 사이 공백은 1칸만 허용하며, 연속 공백을 넣어서는 안 된다.
- **3.2.5** 앱은 닉네임 입력창이 탭되면 입력창을 활성화(Active)하고 키보드와 확인 버튼 영역을 노출해야 한다.
- **3.2.6** 앱은 닉네임이 유효성 검사를 통과하지 못하면 안내 문구를 노출하고 확인 버튼을 비활성화해야 한다.
- **3.2.7** 안내 문구와 플레이스홀더는 §6 문구 표의 문안을 그대로 사용해야 한다.
- **3.2.8** 앱은 닉네임 저장이 성공한 경우에만 계정 정보 화면을 닫고 설정 화면으로 복귀해야 한다.

### 3.3 서비스 탈퇴 (S-003)

- **3.3.1** 앱은 '서비스 탈퇴하기'가 탭되면 탈퇴 알림창을 노출해야 하며, 문구는 §6 문구 표를 따른다.
- **3.3.2** 앱은 탈퇴 알림창에서 '그만두기'가 탭되면 알림창만 닫고 설정 화면을 유지해야 한다.
- **3.3.3** 앱은 탈퇴 알림창에서 '탈퇴하기'가 탭되면 로그인창(A-002-1)으로 이동해야 한다.
- **3.3.4** 앱은 탈퇴 완료 시 완료 토스트를 2초간 노출한 뒤 자동으로 사라지게 해야 한다.
- **3.3.5** 앱은 탈퇴한 사용자가 올린 사진을 삭제하지 않고 익명으로 표시해야 한다.

## 4. 예시

### 4.1 허용되는 경우

- 닉네임 `열다섯글자열다섯글자열다섯글자` — 공백 없이 15자 충족
- 닉네임 `장 서휘` — 글자 사이 공백 1칸

### 4.2 허용되지 않는 경우

- `            ` — 공백만으로 채움 (§3.2.3 위반)
- ` 서휘`, `서휘 ` — 맨 앞/뒤 공백 (§3.2.3 위반)
- `희  훈` — 연속 공백 2칸 (§3.2.4 위반)
- `열 다 섯 글 자 열 다 섯 글 자 열 다 섯 글 자` — 공백 포함 15자 초과 (§3.2.2 위반)

### 4.3 판단이 갈리는 경우

| 상황 | 처리 |
|---|---|
| 한글 자모만 입력 (예: `ㅋㅋㅋ`) | 한글로 취급해 §3.2.1에 따라 허용한다 |
| 16자째 입력 시도 | 입력 UI가 15자에서 선차단한다. §6의 길이 초과 문구는 차단 실패 시 방어선이다 |
| 그룹 내 닉네임 수정 | §3.2.1~§3.2.4 유효성 규칙만 적용하고, 화면 동작(§3.2.5~§3.2.8)은 해당 화면 정책을 따른다 |

## 5. 예외

이 정책에는 예외를 두지 않는다.

## 6. 문구 표

> 확정 문구다. 구현은 아래 문안을 그대로 사용한다. (닉네임 안내 문구의 구현 원본: `Common/NicknameValidator.swift`)

| 화면 | 위치 | 문구 |
|---|---|---|
| 계정 정보 | 입력창 플레이스홀더 | 닉네임을 입력해주세요 |
| 계정 정보 | 빈 닉네임 안내 | 닉네임은 비워둘 수 없어요 |
| 계정 정보 | 허용 외 문자 안내 | 한글, 영문, 숫자, 띄어쓰기만 사용할 수 있어요 |
| 계정 정보 | 앞뒤 공백 안내 | 닉네임의 처음과 끝에는 공백을 사용할 수 없어요 |
| 계정 정보 | 연속 공백 안내 | 공백은 글자 사이에 1칸만 사용할 수 있어요 |
| 계정 정보 | 길이 초과 안내 | 닉네임은 15자까지 사용할 수 있어요 |
| 탈퇴 알림창 | 제목 | 파르페에서 탈퇴하시겠어요? |
| 탈퇴 알림창 | 설명 | 지금까지 올린 사진은 익명으로 표시되며,(줄바꿈)삭제되지 않아요. |
| 탈퇴 알림창 | 버튼 | 탈퇴하기 · 그만두기 |
| 탈퇴 완료 | 토스트 | 파르페 탈퇴가 완료됐어요 |

## 7. 화면 플로우

```
사이드메뉴(설정)
├─ 계정 정보 (S-002)
│    └─ 닉네임 입력창 탭 → 키보드·확인 버튼 노출 (§3.2.5)
│         ├─ 유효성 실패 → 안내 문구 + 확인 버튼 비활성화 (§3.2.6)
│         └─ 확인 탭 → 저장 성공 → 설정 화면 복귀 (§3.2.8)
├─ 서비스 이용약관 → 인앱 웹뷰 (§3.1.3)
├─ 개인정보 처리 방침 → 인앱 웹뷰 (§3.1.3)
├─ 버전 정보 → 표시 전용, 이동 없음 (§3.1.4)
├─ 로그아웃 → 로그인창(A-002-1) 이동
└─ 서비스 탈퇴하기 → 탈퇴 알림창 (S-003, §3.3.1)
     ├─ 그만두기 → 알림창 닫고 설정 유지 (§3.3.2)
     └─ 탈퇴하기 → 로그인창(A-002-1) 이동 (§3.3.3)
                    + 완료 토스트 2초 노출 (§3.3.4)
```

## 8. 미확정 사항 (정책 아님 — 인용 금지)

> 확정되면 §3에 규칙으로 승격하고 여기서 지운다.

- **로그아웃 동작** — 확인 팝업 여부, 이동 화면 미확정 (코드 TODO 상태)
- **서비스 탈퇴·닉네임 저장 서버 연동** — 미구현. §3.2.8·§3.3.4는 서버 연동 완료를 전제로 한다
- **서비스 이용약관·개인정보 처리 방침 URL** — 실제 주소 미확정, 현재 임시 링크
- **사이드메뉴 진입점** — 어느 화면에서 여는지 코드 미연결
