# 온보딩·로그인 정책

> **한 줄 요약** — 앱 실행(A-001), 온보딩·로그인(A-002), 약관 동의(A-003), 그룹 참여(A-004), 그룹 생성(A-005)의 화면 구성, 사용자 동작, 입력 조건 및 화면 이동을 규정한다.
>
> **강제성** — 필수 사항이다. 구현이 이 문서와 다르면 버그로 처리하고, 동작을 바꾸려면 이 문서를 먼저 개정한다.

## 1. 목적

이 문서는 앱 실행부터 로그인·약관 동의까지의 초기 진입 과정과 그룹 참여·생성 과정의 화면 구성 및 동작을 규정한다.

기획·디자인·개발·QA가 온보딩·로그인 영역의 동일한 기준을 확인할 수 있도록 한다.

## 2. 적용 범위

- **적용 대상**: 앱 실행(A-001), 온보딩·로그인(A-002), 약관 동의(A-003), 그룹 참여(A-004), 그룹 생성(A-005)
- **적용 제외**:
  - G-001 및 G-001-Empty의 상세 정책
  - G-002의 상세 정책
  - C-001의 상세 정책
  - S-004 약관 및 개인정보 처리방침의 상세 정책
  - 그룹 내 닉네임의 상세 유효성 규칙

## 3. 규칙

### 3.1 앱 실행 — A-001

- **3.1.1** 앱은 실행 시 스플래시 화면에 서비스 로고를 노출해야 한다.
- **3.1.2** 앱은 스플래시 화면을 2초간 노출해야 한다.
- **3.1.3** 앱은 스플래시 화면에서 로그인 토큰과 앱 버전을 확인해야 한다.
- **3.1.4** 앱은 로그인 토큰이 확인된 경우 G-001로 이동해야 한다.
- **3.1.5** 앱은 미로그인 상태인 경우 A-002로 이동해야 한다.
- **3.1.6** 앱은 네트워크 오류가 발생한 경우 재시도를 안내해야 한다.
- **3.1.7** 앱은 강제 업데이트가 필요한 경우 앱스토어로 이동해야 한다.

### 3.2 온보딩·로그인 — A-002

#### 3.2.1 온보딩

- **3.2.1.1** 온보딩은 총 3개의 페이지로 구성해야 한다.
- **3.2.1.2** 사용자는 좌우 스와이프로 온보딩 페이지를 이동할 수 있어야 한다.
- **3.2.1.3** 앱은 현재 온보딩 페이지를 페이지 인디케이터로 표시해야 한다.
- **3.2.1.4** 각 온보딩 페이지는 해당 페이지의 이미지와 안내 문구를 노출해야 한다.
- **3.2.1.5** 앱은 화면 해상도가 작아지는 경우 온보딩 이미지의 원본 비율을 유지한 상태로 크기를 축소해야 한다.
- **3.2.1.6** 앱은 화면 해상도에 대응하기 위해 온보딩 이미지를 잘라내거나 비율을 변형해서는 안 된다.

#### 3.2.2 로그인

- **3.2.2.1** 앱은 모든 온보딩 페이지에 카카오 로그인 버튼을 노출해야 한다.
- **3.2.2.2** 앱은 모든 온보딩 페이지에 Apple 로그인 버튼을 노출해야 한다.
- **3.2.2.3** 사용자는 3개의 온보딩 페이지 중 어느 페이지에서든 카카오 로그인 또는 Apple 로그인을 진행할 수 있어야 한다.
- **3.2.2.4** 앱은 소셜 로그인 시 소셜 SDK를 호출해야 한다.
- **3.2.2.5** 앱은 소셜 로그인 토큰 발급 후 서버에서 사용자를 등록하거나 조회해야 한다.
- **3.2.2.6** 앱은 서버 사용자 등록 또는 조회 후 JWT를 수령해야 한다.
- **3.2.2.7** 앱은 로그인 절차가 완료되면 A-003으로 이동해야 한다.
- **3.2.2.8** 앱은 약관에 동의하지 않은 사용자의 서비스 진입을 차단해야 한다.

### 3.3 약관 동의 — A-003

- **3.3.1** 앱은 서비스 이용약관과 개인정보 처리방침을 필수 동의 항목으로 제공해야 한다.
- **3.3.2** 사용자는 서비스 이용약관과 개인정보 처리방침에 개별적으로 동의할 수 없다.
- **3.3.3** 사용자가 `모두 동의하기`를 선택하면 서비스 이용약관과 개인정보 처리방침을 모두 동의 상태로 변경해야 한다.
- **3.3.4** 사용자가 전체 동의 상태에서 `모두 동의하기`를 다시 선택하면 서비스 이용약관과 개인정보 처리방침의 동의를 모두 해제해야 한다.
- **3.3.5** 사용자가 서비스 이용약관의 상세 진입 영역을 선택하면 S-004(약관)로 이동해야 한다.
- **3.3.6** 사용자가 개인정보 처리방침의 상세 진입 영역을 선택하면 S-004(개인정보 처리 방침)로 이동해야 한다.
- **3.3.7** 앱은 필수 약관에 동의하지 않은 상태에서 `확인` 버튼을 비활성화해야 한다.
- **3.3.8** 앱은 필수 약관에 모두 동의한 상태에서 `확인` 버튼을 활성화해야 한다.
- **3.3.9** 사용자가 활성화된 `확인` 버튼을 선택하면 G-001-Empty로 이동해야 한다.

### 3.4 그룹 추가 진입 — G-002

- **3.4.1** 사용자가 G-002에서 `그룹 들어가기`를 선택하면 A-004로 이동해야 한다.
- **3.4.2** 사용자가 G-002에서 `그룹 만들기`를 선택하면 A-005로 이동해야 한다.

### 3.5 그룹 참여 — A-004

#### 3.5.1 초대코드 입력

- **3.5.1.1** 그룹 초대코드는 6자리로 구성해야 한다.
- **3.5.1.2** 그룹 초대코드에는 영문 대문자와 숫자만 사용할 수 있다.
- **3.5.1.3** 앱은 초대코드 입력 조건을 충족하지 않은 상태에서 `확인` 버튼을 비활성화해야 한다.
- **3.5.1.4** 앱은 6자리 초대코드가 입력되면 `확인` 버튼을 활성화해야 한다.
- **3.5.1.5** 사용자가 활성화된 `확인` 버튼을 선택하면 앱은 입력한 초대코드의 유효성을 검증해야 한다.
- **3.5.1.6** 앱은 유효한 초대코드가 확인되면 A-004-naming으로 이동해야 한다.
- **3.5.1.7** 앱은 유효하지 않은 초대코드가 입력된 경우 오류 안내를 노출해야 한다.
- **3.5.1.8** 앱은 최대 인원 12명이 모두 참여한 그룹의 초대코드가 입력된 경우 참여 불가 안내를 노출해야 한다.
- **3.5.1.9** 앱은 사용자가 이미 참여한 그룹의 초대코드가 입력된 경우 기참여 안내를 노출해야 한다.
- **3.5.1.10** 앱은 오류 상태에서 사용자가 입력 필드를 다시 선택하면 오류 상태를 해제하고 A-004-Default 상태로 전환해야 한다.

#### 3.5.2 그룹 내 닉네임 입력

- **3.5.2.1** 앱은 초대코드 검증을 통과한 사용자에게 그룹에서 사용할 닉네임 입력 화면을 노출해야 한다.
- **3.5.2.2** 사용자가 그룹 내 닉네임 입력 후 `확인`을 선택하면 앱은 그룹 참여 확인 알림창을 노출해야 한다.

#### 3.5.3 그룹 참여 확인

- **3.5.3.1** 그룹 참여 확인 알림창은 사용자가 참여하려는 그룹명을 표시해야 한다.
- **3.5.3.2** 사용자가 `취소`를 선택하면 앱은 알림창을 닫고 A-004-naming 화면을 유지해야 한다.
- **3.5.3.3** 사용자가 `참여하기`를 선택하면 앱은 사용자를 해당 그룹에 추가해야 한다.
- **3.5.3.4** 그룹 참여가 완료되면 앱은 C-001로 이동해야 한다.

### 3.6 그룹 생성 — A-005

#### 3.6.1 그룹명

- **3.6.1.1** 사용자는 그룹 생성 시 그룹명을 입력해야 한다.
- **3.6.1.2** 그룹명에는 한글·영문·숫자·공백만 입력할 수 있다.
- **3.6.1.3** 그룹명에는 특수문자와 이모지를 입력해서는 안 된다.
- **3.6.1.4** 그룹명은 1자 이상 10자 이하여야 한다.
- **3.6.1.5** 그룹명의 글자 수를 계산할 때 공백도 1자로 계산해야 한다.
- **3.6.1.6** 그룹명의 맨 앞과 맨 뒤에는 공백을 사용할 수 없다.
- **3.6.1.7** 그룹명의 글자 사이에는 공백을 1칸만 사용할 수 있다.
- **3.6.1.8** 그룹명에는 연속 공백을 사용할 수 없다.
- **3.6.1.9** 서로 다른 그룹은 동일한 그룹명을 사용할 수 있다.

#### 3.6.2 그룹 생성 정보

- **3.6.2.1** 사용자는 그룹 생성 시 그룹에서 사용할 닉네임을 입력해야 한다.
- **3.6.2.2** 사용자는 그룹 인원을 1명부터 12명 중 하나로 선택해야 한다.
- **3.6.2.3** 앱은 그룹명과 그룹 속 내 닉네임 입력값이 모두 유효하고 그룹 인원이 선택된 경우에만 `확인` 버튼을 활성화해야 한다.
- **3.6.2.4** 앱은 §3.6.2.3의 조건을 충족하지 않은 경우 `확인` 버튼을 비활성화해야 한다.

#### 3.6.3 그룹 생성 확인

- **3.6.3.1** 사용자가 활성화된 `확인` 버튼을 선택하면 앱은 그룹 생성 확인 알림창을 노출해야 한다.
- **3.6.3.2** 그룹 생성 확인 알림창은 생성하려는 그룹명을 표시해야 한다.
- **3.6.3.3** 그룹 생성 확인 알림창은 그룹명과 인원수를 추후 변경할 수 없음을 안내해야 한다.
- **3.6.3.4** 그룹 생성 확인 알림창은 `취소`와 `만들기` 버튼을 제공해야 한다.
- **3.6.3.5** 사용자가 `만들기`를 선택하면 앱은 그룹을 생성해야 한다.
- **3.6.3.6** 앱은 그룹 생성 시 초대코드를 자동으로 발급해야 한다.
- **3.6.3.7** 그룹 생성이 완료되면 앱은 C-001로 이동해야 한다.
- **3.6.3.8** 앱은 그룹 생성 중 네트워크 오류가 발생한 경우 사용자가 재시도할 수 있도록 해야 한다.

## 4. 예시

### 4.1 허용되는 경우

- 초대코드 `E54W1A` — 영문 대문자와 숫자로 구성된 6자리 코드
- 그룹명 `우와그룹명` — 허용 문자만 사용하고 10자 이하인 경우
- 그룹명 `장 서휘` — 글자 사이에 공백 1칸을 사용한 경우
- 기존 그룹과 동일한 그룹명 — 그룹명 중복은 허용한다

### 4.2 허용되지 않는 경우

- 그룹명의 맨 앞 또는 맨 뒤에 공백을 입력한 경우
- 그룹명 글자 사이에 공백을 2칸 이상 연속으로 입력한 경우
- 그룹명에 특수문자 또는 이모지를 입력한 경우
- 그룹명이 10자를 초과한 경우
- 유효하지 않은 초대코드를 입력한 경우
- 최대 인원 12명이 모두 참여한 그룹에 참여하려는 경우
- 이미 참여 중인 그룹에 다시 참여하려는 경우

├─ 로그인 토큰 확인 → G-001
└─ 미로그인 → A-002 온보딩·로그인
     ├─ A-002-1
     ├─ A-002-2
     └─ A-002-3
          └─ 카카오 로그인 / Apple 로그인
               └─ A-003 약관 동의
                    ├─ 서비스 이용약관 → S-004(약관)
                    ├─ 개인정보 처리방침 → S-004(개인정보 처리 방침)

└─ 그룹 만들기 → A-005
     ├─ 그룹명 입력
     ├─ 그룹 속 내 닉네임 입력
