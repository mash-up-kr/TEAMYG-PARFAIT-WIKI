# 데이터 계약

## `wiki/domains/*.md` 필수 frontmatter

| 필드 | 설명 | 예 |
|---|---|---|
| `title` | 문서 제목 | 앱 사이드메뉴 정책 |
| `domain` | 도메인 slug, 파일명과 일치해야 함 | `app-side` |
| `doc_code` | 문서 코드 (도메인당 1개) | `SM-001` |
| `status` | `draft` \| `confirmed`. 원문 상단에 "초안 — 인용하지 말 것" 배너가 있으면 draft | `draft` |
| `source` | raw 원본 경로 | `raw/app-side/app-side-policy.md` |
| `updated` | 마지막 반영일 (YYYY-MM-DD) | `2026-08-14` |

## 도메인 코드 매핑

각 문서가 원문 안에서 스스로 선언한 코드를 그대로 쓴다 (문서가 자체적으로 "인용은 X §Y 형태로 한다"라고 명시한 값 우선).

| domain | doc_code | 비고 |
|---|---|---|
| onboarding | OB-001 | 원문에 자체 인용 코드 선언 없음 — 위키 쪽에서 임의 부여 |
| canvas | CAN-001~CAN-011 | 도메인 전체 코드가 아니라 문서 안에 정책 11개(CAN-001~CAN-011)가 각자 독립적인 §3.x를 가짐. 자세한 내용은 아래 "canvas 인용 예외" 참고 |
| group-list | G-001 | 원문 YAML frontmatter의 `id`와 동일. 원문 자체 인용 형식: `G-001 §<Part>.3.<규칙번호>` |
| group-side | GSM-001 | 원문 자체 인용 형식: `GSM-001 §3.2.4` |
| app-side | SM-001 | 원문 자체 인용 형식: `SM-001 §3.2.4` |

## 파일명 규칙

- `wiki/domains/<domain>.md` — `<domain>`은 `wiki/routing.json`의 `domains` 값과 정확히 일치해야 한다.
- `raw/<domain>/<domain>-policy.md` — 원본. 사람만 수정하며, 노션 원문이 바뀔 때만 통째로 교체한다.

## 인용 규칙

- 질문에 답할 때는 `<doc_code> §<절번호>` 형식으로 근거를 밝힌다 (예: `SM-001 §3.2.4`, `G-001 §3.3.5`, `GSM-001 §3.2.4`).
- 절 번호가 없는 서술이면 `<doc_code>`만 쓴다.
- 문서 안에서 스스로 "정책 아님 — 인용 금지"라 표시한 섹션은 정책 근거로 인용하지 않는다.

### canvas 인용 예외

`wiki/domains/canvas.md`는 도메인 전체를 대표하는 단일 코드가 없다. 문서 안에 `CAN-001`(캔버스 기본 화면)부터 `CAN-011`(기존 토핑 편집 저장)까지 11개의 독립된 정책이 들어 있고, 각 정책이 스스로 `§3.1`~`§3.8` 같은 규칙 번호를 새로 시작한다. canvas 도메인 질문에 답할 때는:

- frontmatter의 `doc_code`(`CAN-001~CAN-011`)를 그대로 인용하지 말고, 답변 내용이 속한 **해당 정책의 실제 코드**(예: `CAN-004 §3.2`)를 찾아 인용한다.
- 여러 정책에 걸친 답변이면 각각 따로 인용한다 (예: "토핑 추가는 `CAN-004 §3.1`, 배치는 `CAN-007 §3.2`").
