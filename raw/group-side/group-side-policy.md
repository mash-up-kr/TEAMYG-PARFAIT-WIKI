## 1. 목적

이 문서는 그룹 사이드메뉴 영역의 화면 구성·동작·문구를 한 곳에 규정해, 기획·구현·QA가 같은 기준을 보도록 한다.

## 2. 적용 범위

**적용 대상**: 그룹 사이드메뉴(S-101)와 그 하위 화면 — 그룹 내 닉네임 수정(S-102), 그룹 나가기(S-103), 그룹 신고(S-104), 그리고 나가기·신고 완료 후 G-001에 노출되는 완료 토스트.

**적용 제외**:

- 앱 사이드메뉴(설정) 및 계정 정보(S-002)·서비스 탈퇴(S-003) — 앱 사이드메뉴 정책에서 다룬다
- 닉네임 초기 자동 생성 규칙(계정 생성 시 1회 적용) — `S-002-앱닉네임-정책-v0_3.md` §1에서 다룬다

- G-001 목록 재배치 규칙 — `G-001-무한파르페-정책설계.md` §5.1을 따른다

## 3. 규칙

규칙이 8개를 넘어 화면 단위로 §3.1~§3.6으로 묶는다. 인용은 `GSM-001 §3.2.4` 형태로 한다.

### 3.1 그룹 사이드메뉴 화면 (S-101)

- **3.1.1** 앱은 S-101을 C-001(캔버스 메인)에서 진입시키며, 바텀시트가 아닌 **풀스크린 푸시**로 노출해야 한다.
- **3.1.2** 화면은 위에서부터 ① 상단바(뒤로가기 · 그룹명) ② 그룹 속 내 닉네임 ③ 그룹원 목록 ④ 그룹 초대 코드 카드 ⑤ 위험 액션(그룹 나가기 · 그룹 신고하기) 순으로 구성해야 한다.
- **3.1.3** 상단바 타이틀은 현재 그룹의 **그룹명**을 표시해야 한다.
- **3.1.4** '그룹 속 내 닉네임' 입력창은 기본(비활성) 상태에서 현재 **그룹 내 닉네임**과 글자수 카운터 `n/15`를 표시해야 한다. 기본 상태에서는 테두리 gray-100, 카운터 gray-400을 쓰며 삭제(X) 버튼을 노출해서는 안 된다.
- **3.1.5** 그룹원 목록의 라벨은 `그룹원 (N)` 형식으로 표시해야 하며, N은 **본인을 포함한** 현재 그룹 인원 수다.
- **3.1.6** 그룹원 목록의 **첫 행은 항상 본인**이어야 한다. 본인 행은 닉네임 뒤에 ` (나)`를 붙이고 SemiBold · gray-950으로, 그 외 그룹원 행은 Regular · gray-800으로 표시해야 한다.
- **3.1.7** 그룹원 목록은 **전체 행을 펼쳐서** 노출하고, 내용이 화면을 넘치면 **화면 전체 스크롤**로 노출해야 한다. 목록 컨테이너에 별도의 내부 스크롤을 두어서는 안 된다. (디자인의 5행은 375×812 기준 잘림일 뿐 고정 높이가 아니다)
- **3.1.8** 그룹원 목록의 프로필 이미지는 §3.6의 Nametag-Chip 규칙을 따라야 한다.
- **3.1.9** 초대 코드 카드는 라벨 `그룹 초대 코드`, 우측 보조 텍스트, 코드 박스, `복사` 버튼으로 구성해야 한다. 우측 보조 텍스트는 기본 상태에서 `N명 남음`을 표시하며, **N = 12 − 현재 그룹 인원 수**다. (그룹 인원 상한 12명 고정 — `파르페_MD_v6.md`)
- **3.1.10** 그룹 인원이 **상한 12명에 도달하면** 앱은 `N명 남음` 대신 `최대 인원 도달`을 노출해야 한다. `0명 남음`으로 표시해서는 안 된다.
- **3.1.11** 그룹 인원이 상한 12명에 도달하면 앱은 **`복사` 버튼을 비활성화(Disabled)** 해야 하며, 탭해도 클립보드 복사와 `복사됨` 표시가 일어나서는 안 된다.
- **3.1.12** `복사` 버튼을 탭하면 앱은 초대 코드를 시스템 클립보드에 복사하고, 우측 보조 텍스트를 `복사됨`으로 바꿔야 한다.
- **3.1.13** `복사됨`은 **1.5초간 노출한 뒤 자동으로 `N명 남음`으로** 되돌아가야 한다.
- **3.1.14** 위험 액션 영역은 `그룹 나가기`와 `그룹 신고하기` 2개 행으로 구성하고, 점선 테두리와 행 사이 구분선으로 본문과 분리해야 한다. 두 행 모두 gray-500 · Regular로 표시한다.

### 3.2 그룹 속 내 닉네임 수정 (S-102)

닉네임 유효성 규칙(§3.2.1~§3.2.4)은 앱 닉네임 정책(`S-002-앱닉네임-정책-v0_3.md` §2, `S-102-닉네임-정책-v0_3.md` §2)과 **동일하다.** 두 문서 중 하나가 개정되면 나머지도 함께 개정한다.

- **3.2.1** 사용자는 닉네임에 **한글·영문·숫자·공백만** 입력할 수 있으며, 특수문자와 이모지는 입력할 수 없다.
- **3.2.2** 닉네임은 **1자 이상 15자 이하**여야 하며, 공백도 1글자로 센다.
- **3.2.3** 닉네임의 맨 앞과 맨 뒤에는 공백을 넣어서는 안 된다.
- **3.2.4** 글자 사이 공백은 1칸만 허용하며, 연속 공백을 넣어서는 안 된다.
- **3.2.5** 앱은 닉네임 입력창이 탭되면 입력창을 활성화(Active)하고 키보드·삭제(X) 버튼·하단 확인 버튼 영역을 노출해야 한다.
- **3.2.6** 유효성 검사를 **통과한** 상태에서 앱은 입력창 테두리를 cherry-100, 카운터를 gray-400으로 표시하고 `확인` 버튼을 활성화해야 한다.
- **3.2.7** 유효성 검사를 **통과하지 못한** 상태에서 앱은 입력창 테두리와 카운터를 cherry-600으로 바꾸고, 입력창 바로 아래에 해당 안내 문구를 cherry-600으로 노출하며, `확인` 버튼을 **비활성화**해야 한다.
- **3.2.8** 안내 문구와 카운터 표기는 §6 문구 표의 문안을 그대로 사용해야 한다.
- **3.2.9** 앱은 닉네임 저장이 **성공한 경우에만** S-102를 닫고 S-101로 복귀해야 한다. 저장은 서버 API와 **연동 완료** 상태이며, 실제 그룹 내 닉네임 데이터를 갱신한다.
- **3.2.10** 앱은 그룹 내 닉네임이 변경되면 해당 그룹 캔버스에 남아 있는 **이전 작업물의 닉네임 표기를 동기화**해야 한다.
- **3.2.11** 그룹 내 닉네임의 초기값은 계정 생성 시 1회 생성된 값을 재사용하며, 그룹별로 다시 뽑지 않는다. (`S-102-닉네임-정책-v0_3.md` §1)
- **3.2.12** 그룹 내 닉네임 수정은 해당 그룹에만 적용되며, 앱 닉네임(S-002)을 바꿔서는 안 된다.
- **3.2.13** 앱은 닉네임에 대해 **금칙어 검사를 수행하지 않는다.** 유효성 검사는 §3.2.1~§3.2.4로 한정한다.
- **3.2.14** 앱은 **저장하지 않은 입력이 있는 상태에서 뒤로가기(`<`)가 탭되면 이탈 방지 모달을 노출**해야 하며, 경고 없이 화면을 닫아서는 안 된다. 문구는 §6 문구 표를 따른다.
- **3.2.15** 이탈 방지 모달의 구성과 버튼 스타일은 §3.3.2와 동일하며, 버튼은 **좌측 `취소하기` · 우측 `그만두기`** 순으로 배치해야 한다.
- **3.2.16** 앱은 `취소하기`가 탭되면 입력값을 폐기하고 **기존 닉네임을 유지한 채** S-101로 복귀해야 한다.
- **3.2.17** 앱은 `그만두기`가 탭되면 모달만 닫고 S-102를 유지해야 하며, 입력값을 그대로 보존해야 한다.
- **3.2.18** 입력값이 저장된 닉네임과 동일하면(= 변경 없음) §3.2.14의 모달을 노출하지 않고 바로 S-101로 복귀해야 한다.
- **3.2.19** 그룹 내 닉네임은 **같은 그룹의 다른 그룹원과 중복되어도 허용**한다. 앱은 그룹 내 닉네임 중복 여부를 검사해서는 안 되며, 중복을 이유로 저장을 막거나 안내 문구를 노출해서는 안 된다. 유효성 검사는 §3.2.1~§3.2.4로 한정하며 이 목록에 중복 검사는 포함되지 않는다.

### 3.3 그룹 나가기 (S-103)

- **3.3.1** 앱은 `그룹 나가기`가 탭되면 나가기 알림창을 노출해야 하며, 문구는 §6 문구 표를 따른다.
- **3.3.2** 알림창은 경고 아이콘 · 제목 · 설명(2줄) · 버튼 2개로 구성하고, 버튼은 **좌측 `나가기`(보조 스타일: gray-100 배경 + gray-500 테두리) · 우측 `그만두기`(강조 스타일: gray-900 배경 + white 텍스트)** 순으로 배치해야 한다.
- **3.3.3** 앱은 `그만두기`가 탭되면 알림창만 닫고 S-101을 유지해야 한다.
- **3.3.4** 앱은 `나가기`가 탭되면 서버 API와 **연동해 실제 탈퇴 처리**를 수행한 뒤 **G-001(그룹 목록)로 이동**해야 한다.
- **3.3.5** 앱은 G-001 진입 직후 상단에 `{그룹명}에서 나왔어요` 토스트를 노출해야 한다. (§3.5)
- **3.3.6** 앱은 나간 사용자가 올린 토핑을 **삭제하지 않고 익명으로 표시**해야 한다.
- **3.3.7** 앱은 **마지막 1인이 나가면 해당 그룹을 삭제**해야 한다.
- **3.3.8** 나간 그룹은 G-001 목록에서 빠지며, 뒤 토핑들이 한 칸씩 당겨지고 좌/우·변형이 재배정된다. 이는 버그가 아니라 정상 동작이다. (`G-001-무한파르페-정책설계.md` §5.1)

### 3.4 그룹 신고 (S-104) — MVP 공버튼

**MVP 범위에서 S-104는 공버튼이다.** UI 흐름(알림창 → G-001 이동 → 토스트)은 디자인대로 구현하되, **신고 접수·그룹 탈퇴 등 실제 처리는 일어나지 않는다.** `기능정의서-v5.md`의 "MVP는 공버튼" 규정이 유효하다. 닉네임 저장(S-102, §3.2.9)과 그룹 나가기(S-103, §3.3.4)는 서버 연동이 **완료**됐으나, **그룹 신고(S-104)만 예외적으로 서버 미연동 상태를 유지**한다.

- **3.4.1** 앱은 `그룹 신고하기`가 탭되면 신고 알림창을 노출해야 하며, 문구는 §6 문구 표를 따른다.
- **3.4.2** 알림창의 구성과 버튼 스타일은 §3.3.2와 동일하며, 버튼은 **좌측 `신고하기` · 우측 `그만두기`** 순으로 배치해야 한다.
- **3.4.3** 앱은 `그만두기`가 탭되면 알림창만 닫고 S-101을 유지해야 한다.
- **3.4.4** 앱은 `신고하기`가 탭되면 **G-001로 이동**해야 한다.
- **3.4.5** 앱은 G-001 진입 직후 상단에 `신고가 접수되어 운영 정책에 따라 처리됩니다` 토스트를 노출해야 한다. (§3.5)
- **3.4.6** `신고하기`는 **실제로 신고를 접수하지 않는다.** 앱은 신고 데이터를 서버로 전송해서는 안 된다.
- **3.4.7** `신고하기`는 **사용자를 그룹에서 탈퇴시키지 않는다.** 사용자는 해당 그룹에 그대로 남아 있어야 하며, G-001 목록에서도 그룹이 사라져서는 안 된다. §3.3.6~§3.3.8(나가기 후처리)을 적용해서는 안 된다.
- **3.4.8** 신고 사유 선택·입력 단계를 두어서는 안 된다. §3.4는 알림창 1단계로 끝난다.
- **3.4.9** §3.4.5의 토스트 문구는 실제 동작과 일치하지 않는 **공버튼용 안내**다. 실제 신고 기능을 붙일 때 이 절 전체를 개정한다.

### 3.5 완료 토스트 (G-001)

- **3.5.1** 나가기·신고 완료 토스트는 **G-001 상단바 바로 아래**에 화면 전체 폭으로 노출해야 한다.
- **3.5.2** 토스트 배경은 Black-75(`rgba(14,14,14,0.75)`), 텍스트는 `Body/B02/B02_SB`(SUIT SemiBold 14) · **Melon-600(`#2AE6AE`)** 을 사용해야 한다. 좌우 여백 16px, 상하 여백 12px. 나가기·신고 토스트 모두 동일하며, 신고 토스트에 Cherry 계열을 써서는 안 된다.
- **3.5.3** 토스트는 **2초간 노출한 뒤 자동으로 사라져야 한다.** (앱 사이드메뉴 정책의 탈퇴 완료 토스트와 동일)
- **3.5.4** §3.5의 토스트는 **닉네임을 포함하지 않는 시스템 토스트**이므로 컬러가 Melon-600으로 고정된다. 닉네임이 포함되는 캔버스 액션 토스트(C-001)는 §3.6.4의 매핑을 따르며, 두 규칙을 섞어서는 안 된다.

### 3.6 프로필 이미지(Nametag-Chip) 및 컬러 규칙

`S-101-프로필-닉네임-컬러-규칙-v0.2.md`와 동일한 규칙이며, S-101 그룹원 목록에도 그대로 적용된다.

#### 3.6.1 프로필 이미지 정책

- 프로필 사진은 **닉네임 첫 글자가 들어간 원형 프로필 이미지(Nametag-Chip)** 로 노출한다.
- Nametag-Chip은 **6개 컬러**(연핑크, 진핑크, 체리, 그레이, 멜론, 푸딩)별로 **각 2개 타입**이 존재하며, **총 12종 중 1종**이 랜덤 배정된다.

#### 3.6.2 Nametag-Chip 타입 고정 정책

- 타입은 **계정 생성 시 1회 랜덤 배정**되며, 이후에는 변경되지 않는다.
- 동일한 닉네임을 쓰는 사용자라도 **계정이 다르면 서로 다른 타입**이 배정될 수 있다.
- 한 번 배정된 타입은 **모든 화면에서 동일하게 유지**되며, 앱 재접속·그룹 변경에도 변하지 않는다. 별도의 타입 변경 기능이 추가되지 않는 한 계정이 유지되는 동안 동일 타입을 쓴다.

> 예시 — 계정 A(닉네임 `홍씨`) → Type 1 배정 → 모든 화면에서 Type 1 유지 / 계정 B(닉네임 `홍씨`) → Type 8 배정 → 모든 화면에서 Type 8 유지.
> 즉, 닉네임이 같아도 계정이 다르면 서로 다른 Nametag-Chip과 토스트 닉네임 컬러를 가질 수 있다.

#### 3.6.3 S-101 그룹원 목록 적용

- **3.6.3.1** 그룹원 목록의 각 행은 해당 계정에 배정된 Nametag-Chip을 **그대로** 노출해야 하며, 그룹 단위로 재배정해서는 안 된다.

#### 3.6.4 토스트 알림 닉네임 컬러 매핑 정책

공용 캔버스(C-001)에서 액션 발생 시 동접 중인 그룹원에게 토스트 알림이 뜬다. 토스트 속 **닉네임 텍스트**는 해당 유저의 Nametag-Chip 타입에 따라 아래와 같이 **강제 매핑**된다.

| 컬러 (타입) | 닉네임 텍스트 컬러 |
| --- | --- |
| 연핑크 (Type 1, 2) | Cherry-200 |
| 진핑크 (Type 3, 4) | Cherry-300 |
| 체리 (Type 5, 6) | Cherry-400 |
| 그레이 (Type 7, 8) | White |
| 멜론 (Type 9, 10) | Melon |
| 푸딩 (Type 11, 12) | Pudding |

#### 3.6.5 Grouptag-Chip 내 타임스탬프 컬러 매핑 정책

G-001에서 그룹 대표 토핑과 함께 노출되는 Grouptag-Chip 속 **Timestamp 텍스트**는, 해당 그룹에서 **마지막으로 변화를 가한 유저**(토핑 추가 · 토핑 편집 · 배경 추가 · 배경 변경)의 Nametag-Chip 타입에 따라 아래와 같이 **강제 매핑**된다.

| 컬러 (타입) | Timestamp 텍스트 컬러 |
| --- | --- |
| 연핑크 (Type 1, 2) | Cherry-100 |
| 진핑크 (Type 3, 4) | Cherry-200 |
| 체리 (Type 5, 6) | Cherry-300 |
| 그레이 (Type 7, 8) | White |
| 멜론 (Type 9, 10) | Melon |
| 푸딩 (Type 11, 12) | Pudding |

### 4.3 판단이 갈리는 경우

| 상황 | 처리 |
| --- | --- |
| 한글 자모만 입력 (예: `ㅋㅋㅋ`) | 한글로 취급해 §3.2.1에 따라 허용한다 |
| 16자째 입력 시도 | 입력 UI가 15자에서 선차단한다. §6의 길이 초과 문구는 차단 실패 시 방어선이다 |
| 그룹 내 닉네임과 앱 닉네임이 다름 | 정상이다. 두 값은 독립이며 S-101은 그룹 내 닉네임만 수정한다 (§3.2.12) |
| 같은 그룹 안에 동일한 닉네임을 쓰는 그룹원이 2명 이상 | 정상이다. 그룹 내 닉네임 중복은 허용되며 앱은 이를 막거나 경고해서는 안 된다 (§3.2.19) |
| 그룹원이 상한(12명)에 도달 | 보조 텍스트를 `최대 인원 도달`로 바꾸고 `복사` 버튼을 Disabled 처리한다 (§3.1.10~§3.1.11). 12명 초과 가입 차단은 A-004에서 함께 처리한다 |
| 12명 도달 상태에서 `복사` 탭 | 아무 동작도 하지 않는다. `복사됨`을 노출해서는 안 된다 (§3.1.11) |
| 12명 → 1명이 나가서 11명이 됨 | 보조 텍스트가 `1명 남음`으로 돌아오고 `복사` 버튼이 다시 활성화된다 |
| 신고 후에도 그룹이 목록에 남아 있음 | 정상이다. S-104는 공버튼이므로 탈퇴가 일어나지 않는다 (§3.4.7) |
| 신고 토스트는 떴는데 아무 일도 없음 | 정상이다. MVP 공버튼 동작이다 (§3.4.6, §3.4.9) |
| 닉네임을 고치다 뒤로가기 | 이탈 방지 모달을 띄운다 (§3.2.14). 단 입력값이 기존 닉네임과 같으면 모달 없이 복귀한다 (§3.2.18) |
| 이탈 방지 모달에서 `그만두기` 탭 | S-102에 머무르며 **입력값이 그대로 남아 있어야 한다** (§3.2.17). 입력창을 초기화하면 버그다 |
| 나가기 직후 토스트가 뜨기 전에 사용자가 다른 그룹으로 진입 | 토스트는 G-001에 귀속되므로 노출하지 않는다 |

## 6. 문구 표

확정 문구다. 구현은 아래 문안을 그대로 사용한다.

- **마침표를 쓰지 않는다.** v0.2에서 카피 톤을 통일했으므로, 디자인 원본(`499:3589`, `1799:9398`)에 마침표가 있어도 **이 표를 따른다.**
- **알림창 버튼 문안 규칙** — 좌측 버튼은 **제목의 동사를 그대로 받고**, 우측 버튼은 **항상 `그만두기`**(= 지금 하려는 행동을 중단)로 고정한다. 이 규칙 때문에 이탈 방지 모달의 제목 동사를 `그만두다` → `취소하다`로 바꿨다. 제목이 `닉네임 수정을 그만둘까요?`이면 좌·우 버튼이 모두 `그만두기`가 되어 뜻이 충돌한다.

  | 제목 | 좌측(보조) | 우측(강조) |
  | --- | --- | --- |
  | 그룹에서 나갈까요? | `나가기` | `그만두기` |
  | 그룹을 신고할까요? | `신고하기` | `그만두기` |
  | 닉네임 수정을 취소할까요? | `취소하기` | `그만두기` |

    │    │              └─ 복사 탭 → 클립보드 복사 + `복사됨` → 1.5초 후 복귀 (§3.1.12~§3.1.13)
    │    └─ 12명 도달 → `최대 인원 도달` · 복사 Disabled (§3.1.10~§3.1.11)
    ├─ 그룹 나가기 → S-103 알림창 (§3.3.1)
    │    ├─ 그만두기 → 알림창 닫고 S-101 유지 (§3.3.3)
    │    └─ 나가기   → 그룹 탈퇴 → G-001 이동 (§3.3.4)
    │                  + 토스트 `{그룹명}에서 나왔어요` 2초 (§3.3.5, §3.5.3)
    │                  + 내 토핑 익명 보존 (§3.3.6) / 마지막 1인이면 그룹 삭제 (§3.3.7)
    └─ 그룹 신고하기 → S-104 알림창 (§3.4.1)  ※ MVP 공버튼
         ├─ 그만두기 → 알림창 닫고 S-101 유지 (§3.4.3)
         └─ 신고하기 → G-001 이동 (§3.4.4)
                        + 토스트 `신고가 접수되어 운영 정책에 따라 처리됩니다` 2초 (§3.4.5)
                        ※ 신고 접수 없음 (§3.4.6) · 그룹 탈퇴 없음 (§3.4.7)
